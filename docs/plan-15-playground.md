# 계획 15 — REMO OS 놀이터 (관계 맵을 캐릭터 놀이터로)

날짜: 2026-10-08. 대상: 홈의 "열 명이 맞물린 방식을 이름 없이 봅니다" 섹션. 코드: `site/assets/playground.js`, 스타일은 `landing.css`의 "놀이터" 블록.

## 2. 철학을 어떻게 시각화했나

| 철학 | 구현 |
|---|---|
| 각자의 형태를 잃지 않은 채 맞물린다 | 노드 10개가 서로 다른 윤곽·크기·장식(머리 뭉치, 더듬이, 새싹, 둥근 귀, 삐죽 머리, 리본, 머리띠, 주근깨, 모자, 고양이 귀)을 가진 캐릭터. 같은 둥근 문법 안의 개별성 |
| 맞물림 = 선 하나 | 선택한 관계 유형의 간선이 실제 스프링이다. 유형을 바꾸면 끌어당기는 상대가 바뀌어 캐릭터들이 몸으로 재배치된다 |
| 재구성 가능한 | 잡아서 던질 수 있고, 흔들어도 이어진 사람끼리 다시 모인다 |
| 이름 없이 | 이름·역할 없음. 노드 번호는 접근성 라벨에 노출하지 않음 |
| 유형의 성격을 선으로 | 같이 하면 강해지는 = 굵고 단단한 실선, 서로 메워주는 = 방향 화살표(보완하는 쪽→받는 쪽), 손발이 맞는 = 같은 박자로 흐르는 점선 |
| 연결되지 않은 사람 | 이 유형에서 선이 없는 사람은 옅은 색에 무표정으로 두리번거린다. 이어진 사람은 웃고 서로를 바라본다 |

## 3. 인터랙션 범위

마우스(호버·잡기·던지기·클릭 뛰기), 터치(잡기·던지기, 캐릭터 위에서만 스크롤 잠금), 키보드(Tab으로 캐릭터, 방향키로 밀기, Enter·Space로 뛰기), 휴대폰 기울이기(권한 허용 시 중력 방향이 기울기를 따라간다, 터치 기기에서만 버튼 노출), 버튼 3종 유형 전환과 "흔들어 보기", 화면 크기에 따라 캐릭터 크기·벽·위치가 다시 계산된다. 뛰면 이어진 사람들이 0.14초 뒤 따라 뛴다.

## 4. 정직성과 개인정보

- 데이터는 `relations.json` 그대로. 방향(cover)은 plan-06의 "보완하는 → 받는" 규약을 따른 해석이다.
- 호버 말풍선은 "이 유형에서의 관계 N개"만 말한다. 연결 수가 쏠린 사람은 당사자가 알아볼 수 있다는 plan-06의 우려는 그대로 남아 있다(팀 동의 대기). 방향별(주는/받는) 수는 일부러 글로 보여 주지 않았다.

## 5. 검증과 한계

확인함: 데스크톱 폭과 375px에서 렌더, 가로 스크롤 0, 물리 엔진 로드와 캐릭터 10개·선 렌더, 마우스 드래그, 유형 전환(선·화살표·말풍선), 모바일 정사각형 레이아웃.
**확인하지 못함:** 실기기 터치 던지기와 스크롤 충돌, 휴대폰 기울이기(권한 흐름 포함), `prefers-reduced-motion` 경로, 키보드 조작 전체, 스크린리더, Safari·Firefox, 성능(프레임, 배터리). 던질 때 벽 밖으로 나가던 현상은 안쪽으로 되돌리는 보정을 넣었으나 반복 시험하지 않았다. 캐릭터 장식 10종과 표정은 임의 디자인이라 팀 확인이 필요하다.
