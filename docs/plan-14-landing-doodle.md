## 1. 출발점: 사용자가 준 로고 세 장

흰 채움 + 굵은 검정 외곽선 + 눈 두 개. 주황 원 배지, 블루 원 배지, 선화 REMO 워드마크(R에 눈과 코, 궤도와 점). 이 문법은 3D 크롬보다 **2D 스티커·두들**이다. 그래서 라이브러리 없이 SVG로 만든다(README 라이브러리 0 예산과도 맞는다).

## 2. 기본 디자인 이론을 어디에 썼나

| 이론 | 적용 | 확인 방법 |
|---|---|---|
| 초점은 화면당 하나 | 첫 화면은 워드마크 하나. 그 아래 문장 둘, 힌트 하나 | 스크린샷 |
| 위계는 크기·굵기·간격으로 | 글자 크기 16 · 20 · 25 · 31 · 39 · 49(1.25배 비율), 제목 800 / 본문 400 | CSS 토큰 |
| 근접성(게슈탈트) | 간격 8px 배수. 묶음 안 8~24, 섹션 사이 96(모바일 64) | CSS 토큰 |
| 유사성 | 모든 외곽선 3px, 모서리는 둥글게, 흰 채움. 로고 선 굵기를 UI에 그대로 | CSS `--line` |
| 연속성·폐합 | 궤도 타원이 점들을 잇고, 관계 선이 노드를 잇는다 | 스크린샷 |
| 색 비율 60·30·10 | 종이 약 60, 잉크(선·글자) 약 30, 주황 약 10. 블루는 관계 섹션 한 곳만 | 눈으로 확인, 비율 계산은 안 함 |
| 명암비 | 잉크/종이 16.1, 잉크/주황 6.1, 흰/블루 5.7, 주황 글자/종이 4.8. **잉크/블루 3.1은 글자에 쓰지 않음** | 계산 스크립트 실행값 |
| 읽기 편한 줄 길이 | 본문 `max-width: 52ch`, 한국어 `keep-all`, 제목 `text-wrap: balance` | CSS |
| 터치 대상 | 버튼·칩·내비 ≥ 44px, 모바일 궤도 점 누르는 영역 45px(실측) | JS 실측 |
| 어포던스·피드백 | 힌트 문장, `cursor: grab`, 호버 시 채움 색 변화, 눌림 1px | 동작 확인 |
| 움직임은 정보 또는 입력의 응답일 때만 | 궤도 = 프로젝트 위치(눌러서 이동), 눈 = 포인터 응답, 드래그 = 글자의 복원력. 장식용 자동 연출은 없음 | 코드 |

## 3. 브랜드 철학을 어디에 썼나 (가이드 v4)

| 철학 | 구현 |
|---|---|
| 각자의 형태를 잃지 않은 채 맞물린다 | 관계 맵. 노드 10개는 각자 눈 달린 원이고 이름은 없다. 유형 버튼으로 맞물림이 바뀐다 |
| 재구성 가능한 | 워드마크 글자를 잡아 던질 수 있고, 놓으면 제자리로 돌아온다(감쇠 스프링) |
| 둥글고 통통한, 손맛 | 원본 선화를 트레이싱한 경로를 그대로 사용. 프로젝트 카드와 팀 이름은 손으로 붙인 듯 ±1~2도 기울고 호버 시 반듯해진다 |
| 단색 운용, 한 번에 한 색 | 섹션 단위 모드: 종이+주황(기본) / 블루(관계) / 주황(문의). 한 섹션에 두 색 면을 섞지 않는다 |
| 위트 | R의 눈이 포인터를 따라가고 가끔 깜빡인다. 문의 섹션의 큰 R도 같다 |
| 정직(이 저장소의 콘텐츠 기준) | 문구·프로젝트·팀 이름·관계 데이터 모두 기존 사이트와 `relations.json`에서 가져왔다. 없는 값을 만들지 않았다. 팀 역할은 비웠다 |

## 4. AI 티가 나지 않게 한 선택 (금지가 아니라 이유가 있는 선택)

- 그라디언트·글래스·그림자 없음. 깊이는 선과 면 색으로만.
- 보라/파랑 그라디언트, 아이콘 타일, 3열 균등 카드 없음. 하는 일은 카드가 아니라 **줄(row)**, 프로젝트는 12열 위에서 비대칭 배치.
- 이모지·가짜 수치·가짜 후기 없음.
- 서체 하나(Pretendard), 굵기 두 가지 중심.
- 장식 모션 없음. 모든 전환은 160~200ms, `transform`·`opacity`·`fill`만, 오버슈트 이징 없음(드래그 복원 스프링은 사용자 입력에 대한 물리 응답이라 예외).

## 6. 만든 방법 (재현 가능)

1. `docs/assets-src/`에 원본 로고 3장 보관.
2. `docs/tools/trace-wordmark.py`: 선화에서 글자별 채움 영역을 찾아 외곽 경로로 변환(연결 성분 → 팽창 → 경계 추적 → 단순화 → 평활). 눈 구멍처럼 작은 루프는 버리고 눈은 SVG 원으로 따로 움직인다.
3. `docs/tools/inject-wordmark.py`: 결과를 `landing.html`에 넣는다.
4. `landing.js`: 글자 스프링, 궤도, 눈 추적, 관계 그래프. 화면 밖이면 갱신하지 않는다.

## 7. 검증한 것과 못 한 것

확인함(데스크톱 브라우저 창 하나, 375px 에뮬레이션):
- 워드마크가 원본 선화와 거의 같게 나온다. 글자 드래그와 복귀, 눈 추적, 궤도 점 호버 라벨(DOM 상태), 관계 유형 전환과 읽기 문구, 모든 섹션 렌더, 콘솔 오류 0, 375px에서 가로 스크롤 0, 모바일 궤도 점 누르는 영역 45px.

**확인하지 못함:**
- 실기기 터치(터치에서는 스크롤을 지키려고 드래그 대신 "눌림"만 한다. 이 경로는 코드만 있고 터치 입력으로 실행해 보지 않았다).
- `prefers-reduced-motion` 경로, 키보드 탐색 전체 흐름, 스크린리더.
- Safari·Firefox. 모바일 점 영역에 쓴 CSS `r` 속성의 지원은 실측하지 않았다.
- 성능(LCP·INP). 별도 번들이 없어 가볍다고 예상하지만 측정하지 않았다.
- 궤도 점은 천천히 움직이는 링크라 정확히 누르기 어려울 수 있다. 호버·포커스 때 멈추고 모바일 영역을 키웠으나 사용성 테스트는 하지 않았다.
