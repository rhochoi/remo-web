기준: [decisions.md](decisions.md) 2026-09-17 결정 + 5섹션 포트폴리오 골격을 "필터" 논리로 재배치.
원칙: **파격은 첫 화면에만, 스크롤 이후는 정석대로.** 원페이지, 서브페이지 없음, 프로젝트 상세는 외부 링크.

스크롤은 브라우저 네이티브. 부드러운 스크롤 라이브러리 금지(README 기술 기준).

## 섹션별 명세

### 0. 관계 맵 — 첫 화면

- **목적**: 설명하지 않고 재현한다. 만지지 않는 사람은 대상이 아니다.
- **필수 요소**: 노드 11개(이름·설명 없음), 필터 5개(강점 / 보완 / 트리거 충돌 / 소통 불일치 / 시너지), 필터 전환 시 선이 다시 그려짐.
- **텍스트**: 없음. 슬로건·서브카피·CTA를 두지 않는다.
- **구현**: SVG 또는 2D 캔버스. 3D·WebGL 금지. `prefers-reduced-motion`이면 전환 애니메이션 없이 즉시 재배치.
- **접근성**: 필터 5개는 실제 `<button>`으로, 키보드 포커스 표시. 스크린리더용으로 각 필터의 의미를 `aria-label`에만 둔다(시각적으로는 무텍스트 유지).
- **첫 화면 규칙**: 390px에서 맵 전체 + 필터 5개가 스크롤 없이 보여야 한다.
- **데이터 출처**: 팀 진단 데이터. 익명화 기준 미정 → 확정 전에는 노드 배치·연결만 쓰고 개인 식별 가능한 속성은 넣지 않는다.
- **차단 요인**: 로고 벡터 원본 미확보(형태 언어 일치 불가), 익명화 기준 미정.

### 1. 받는 일 / 받지 않는 일

- **목적**: 첫 화면이 행동으로 거른다면 이 섹션은 문장으로 거른다. 대상을 좁혀 말한다.
- **필수 요소**: 두 열 — "이런 일을 받습니다" / "이런 일은 받지 않습니다". 각 3~5개 항목, 항목당 한 문장.
- **금지**: 팀 소개, 슬로건, 비전. 여기는 조건이지 자기소개가 아니다.
- **데이터 출처**: 팀 합의.
- **차단 요인**: "받지 않습니다" 문구 팀 합의 미완료. 합의 전에는 섹션을 비워두지 말고 **섹션 자체를 렌더링하지 않는다.**

### 2. Featured Projects

- **목적**: "어떤 문제를 끝까지 해결해 봤는가"의 근거. 전수 목록이 아니라 선별 2~3개.
- **카드 구성** (좌: 썸네일 / 우: 명세):
  - 프로젝트명 + 한 줄 — 목적과 대상
  - 역할 분담 — 기획 / 디자인 / 개발 등 팀 내 기여
  - 성과 또는 산출물 — **모든 수치에 표본 수·측정 시점·측정 방법 병기** ("눈금 붙은 수치" 모델). 수치가 없으면 산출물(배포 링크, 분석 문서)만 쓴다.
  - 사용 도구 태그 — 실제 사용한 것만
  - 상세 링크 — 노션 또는 배포 URL. 사이트 안에 기획서·코드를 펼치지 않는다.
- **상호작용**: "벗겨내기" 모델 적용 후보 — 카드 기본은 산출물, 토글하면 "말해지지 않은 것"(한계·미측정·실패). 적용 여부는 사례 2개 이상 확보 후 결정.
- **레이아웃**: 균등 그리드 금지. 카드 3개면 폭·오프셋을 달리한다. 기울기는 -2 / -1 / +1deg 중에서만.
- **빈 값 처리**: 현재 1개 확보. **없는 사례를 만들어 채우지 않는다.** 확보된 1개만 렌더링하고, "준비 중" 자리표시 카드도 두지 않는다.
- **차단 요인**: 사례 2개 미확보.

### 3. Team

- **목적**: 얼굴이 아니라 전문성과 역할.
- **카드 구성**: 이미지(실사진 또는 톤 통일된 캐릭터 — 팀 내 하나로 통일), 이름 + 포지션, 담당 업무 한 줄, 개인 링크(GitHub / LinkedIn / 블로그 중 본인이 공개한 것만).
- **데이터 출처**: 팀원 본인 제출. 대리 작성 금지.
- **빈 값 처리**: 링크 없는 팀원은 링크 영역을 비운다. 이미지 미제출은 이니셜 원형 단색 처리(브랜드 잉크 / 근백색).
- **관계 맵과의 연결**: 섹션 0의 노드 11개와 팀원 수가 일치하는지 확인. 불일치하면 어느 쪽이 맞는지 결정 기록 필요.

### 4. Work Process & Tools

- **목적**: 어떻게 일하는지. 현재 구조에서 유일하게 "우리 이야기"를 하는 곳이지만, 형용사 없이 절차와 도구만 쓴다.
- **Work Process**: 3~4단계 파이프라인. 초안: 문제 정의 → 빠른 프로토타입 → 사용자 테스트 → 배포/회고. 각 단계에 산출물 명사 하나씩(예: 정의 문서 / 클릭 가능한 프로토타입 / 테스트 기록 / 회고 문서).
- **Tools**: 카테고리별 태그 — 기획·디자인 / 개발 / 협업. 실제 사용 중인 것만.
- **레이아웃**: 단계는 상승 기울기 배치 허용(형태 앵커 "상승 기울기와 손맛"). 태그는 라운드 20px 이상 필.
- **차단 요인**: 없음. 지금 작성 가능.

### 5. Contact

- **목적**: 의도적으로 무거운 전환. 시간을 들이지 않는 문의는 거른다.
- **형태**: 폼. 원클릭 메일 링크 단독 배치 금지.
- **필수 입력 (초안)**: 소속·역할 / 해결하려는 문제 한 단락 / 지금까지 시도한 것 / 기대하는 협업 형태 / 일정·예산 범위(선택 아님) / 연락처.
- **처리**: 정적 사이트이므로 폼 백엔드 필요. 후보: Formspree 무료 티어 또는 `mailto:` + 필수 항목을 본문 템플릿으로 채우기. **결정 대기.**
- **응답 약속**: 명시하지 않는다. "24시간 내 답변" 같은 문구는 전환 최적화 언어다.

## 미해결 항목 → 차단 맵

| 미해결 | 차단하는 섹션 | 없이 진행 가능한 범위 |
|---|---|---|
| 로고 벡터 원본 | 0, 전체 헤더 | 0을 제외한 1~5 마크업·스타일 |
| 팀 진단 데이터 익명화 기준 | 0 | 배치·연결 로직 개발(실데이터 미투입) |
| 사례 2개 미확보 | 2 | 1개 카드로 레이아웃 검증 |
| "받지 않습니다" 문구 합의 | 1 | 섹션 미렌더링 상태로 나머지 진행 |
| 폼 백엔드 선택 | 5 | 프런트 마크업 |

**지금 당장 착수 가능**: 4번 전체, 3번 카드 컴포넌트(데이터 대기), 2번 카드 컴포넌트(1개), 5번 마크업, 전역 토큰·타이포·헤더.

## 이 문서가 결정하지 않은 것

- 섹션 간 전환 연출(있다면 transform·opacity만, 화면당 1~2개)
- 다크 모드 여부 — 블루 모드 단일 운용이므로 기본은 라이트 근백색. 다크는 별도 결정.
- 다국어 — 국문 단일로 시작.
