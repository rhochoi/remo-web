## 섹션별 명세

### 0. 정의문 — 첫 화면

- **목적**: 외부인이 3초 안에 "무엇을 하는 누구인가"를 안다. 시각 사용자와 보조기기 사용자가 **같은 텍스트**를 본다(숨긴 h1 같은 이중 구조 금지).
- **문장** (사실만으로 조립, 2026-09-17):
  - `<h1>` "문제를 받아 실행으로 증명하는 열 명의 학생 협동조합, 리모."
  - 서브 "데이터 분석 · 디자인 · 프로토타입으로 끝까지 풀어냅니다."
- **구절별 근거**: "실행으로 증명" = 노션 미션 원문 술어 / "열 명·학생·협동조합" = 노션 팀원 DB·README·협동조합 문서 / 세 명사 = 노션 태스크·프로젝트 DB에서 확인된 산출물 유형. "프로토타입"은 팀 확인 완료(2026-09-17).
- **기각안**: 미션 원문 그대로(범용문, 4패널 만장일치 기각) / 대상 고객 명시(대상 미확인 → 지어내기) / "빠르게 검증"(측정 불가 형용사).
- **타이포**: h1 `clamp(34px, 6.5vw, 72px)`, `keep-all`, `-0.03em`. 390px에서 34px이면 줄당 약 10자 → "협동조합," 같은 어절이 넘치지 않음(실측 필수). 좌측 정렬.
- **첫 화면 규칙**: h1 + 서브 + 헤더가 390×664(Safari 툴바 제외)에 스크롤 없이 들어간다.
- **CTA**: 없음. 스크롤이 CTA다.
- **차단 요인**: 없음. 문장은 팀 확인 전에도 근거가 있어 배포 가능.

### 관계 맵 — 조건부 섹션 (첫 화면에서 강등)

- **원래 결정**: decisions.md "무텍스트 관계 맵". 콘셉트는 유지하되 **첫 화면에서 내린다.**
- **강등 이유**: (1) `role="img"` 명세가 "만지는 도구" 선언과 모순 — 보조기기에 상호작용이 존재하지 않음(WCAG 1.1.1·1.3.1·2.1.1) (2) 실데이터 없는 맵은 "없는 것을 만들지 않는다" 규칙 위반 (3) 필터 라벨(트리거 충돌·소통 불일치)은 내부 진단 용어라 외부인이 의미를 모름.
- **재도입 3조건**: ① 팀 진단 데이터 스키마 + 익명화 기준 확정 ② 노드를 `<button>`으로, 필터 상태를 텍스트로 요약(`aria-live`) ③ 필터 라벨을 외부인 언어로 재작성.
- **위치**: 조건 충족 시 1번 "방향"과 2번 사이. 첫 화면 복귀는 별도 결정.
- **구현 제약**: SVG, 3D 금지, reduced-motion 시 즉시 재배치, 노드 타깃 ≥24px, 선·노드 명암 ≥3:1(1.4.11). **블루(#1E548C) 위 잉크(#0A0A0A) 조합 금지** — 2.5:1로 미달.

### 1. 방향 — 무엇을, 왜, 어디로

- **목적**: 외부인이 한 화면에서 "이 팀이 뭘 하고 왜 하는지"를 안다. 설명문이 아니라 팀이 이미 써 둔 문장을 그대로 세운다.
- **필수 요소** (전부 노션 REMO.core TEAM 페이지 원문, 2026-09-17 확인):
  - 미션(제목급): "우리는 가치와 문제를 비즈니스로 풀어내며 실행으로 증명한다."
  - 비전 2년차: "혼자가 아닌 팀으로 선순환하며, 시장의 평가 속에서 성장한다."
  - 가치 5: 학습(성장) / 협력 / 신뢰(안전감) / 책임(설명) / 실행(실험)
  - 지금 분기 목표 + 기간: "팀이 서로 연결되어 협업할 수 있는 시스템을 구축한다." (2026.09 → 2026.12)
  - 의사결정 기준: 1차 만장일치 → 2차 80% → 3차 60%
- **제외**: 매출·수익 수치(내부 OKR), 근무 요일·지각비 등 운영 규칙, 팀 소개 산문.
- **갱신 규칙**: 분기 목표는 분기마다 노션 OKR과 맞춘다. 노션 원문이 바뀌면 사이트도 바꾸고, 사이트에서 먼저 고치지 않는다.
- **레이아웃**: 미션 72px 좌측 정렬 `keep-all`. 비전은 잉크 블록(-1deg), 가치는 블루 필, 분기 목표는 4px 아웃라인 카드.
- **차단 요인**: 없음.

### 2. 받는 일 / 받지 않는 일

- **목적**: 첫 화면이 행동으로 거른다면 이 섹션은 문장으로 거른다.
- **필수 요소**: 두 블록 — "이런 일을 받습니다"(아웃라인) / "이런 일은 받지 않습니다"(블루, +1deg, 더 넓게). 각 3~5개, 항목당 한 문장.
- **금지**: 팀 소개, 슬로건, 비전. 여기는 조건이지 자기소개가 아니다.
- **데이터 출처**: 팀 합의.
- **차단 요인**: "받지 않습니다" 문구 팀 합의 미완료. 합의 전에는 **섹션 자체를 렌더링하지 않는다.**

### 3. 포트폴리오

- **목적**: 근거. 전수 목록이 아니다. 2026-09-17 기준 4개 전부 "진행중"이므로 제목은 "지금 하고 있는 네 가지 일" — 완료 프로젝트가 생기면 재검토.
- **대상 4개 (확정)**: DATAFLOW 2 / K-Pipe / PLN / Moodism 무디즘. 각 카드는 노션 프로젝트 페이지로 연결.
- **카드 구성**: 대표 썸네일 / 프로젝트명 / 한 줄(목적과 대상) / 역할 분담 / 산출물 또는 성과 / 도구 태그 / "노션에서 자세히 →"
- **수치 규칙**: 모든 수치에 표본 수·측정 시점·측정 방법 병기. 없으면 산출물 링크만.
- **레이아웃**: 2행 비대칭 — 1행 DATAFLOW 2(잉크, 넓게, -1deg) + K-Pipe(아웃라인) / 2행 PLN(아웃라인, +1deg) + Moodism(블루, 넓게). 균등 그리드 금지.
- **확보 값**: K-Pipe·Moodism·PLN 한 줄·기간·사람·현재 단계(노션 원문). **미확보**: DATAFLOW 2 설명, 도구 태그, 썸네일 — 비워 둔다. 상세는 [plan-03-portfolio.md](plan-03-portfolio.md).
- **차단 요인**: DATAFLOW 2 설명(팀 확인), PLN 시작 시점, 도구 목록.

### 4. 팀

- **목적**: 얼굴이 아니라 전문성과 역할.
- **대상 10명 (확정, 표기명)**: 브루노 / 쏠 / 조이 / 정우 / 막스 / 유진 / 로 / 겸 / 이든 / 비크
- **카드 구성**: 이니셜 원형(잉크 또는 블루 단색) / 이름 / 포지션 / 담당 업무 한 줄 / 개인 링크(본인이 공개한 것만).
- **레이아웃**: 232px 카드 플로우 랩, 카드마다 상단 오프셋을 달리해 균등 그리드를 깬다.
- **데이터 출처**: 팀원 본인 제출. 대리 작성 금지. 미제출 항목은 비운다.
- **관계 맵과의 연결**: 노드 10개 = 팀원 10명. 일치 확인 완료.
- **차단 요인**: 포지션·담당 한 줄·링크 미수집.

### 5. 문의

- **목적**: 의도적으로 무거운 전환. 시간을 들이지 않는 문의는 거른다.
- **형태**: 폼. 원클릭 메일 링크 단독 배치 금지.
- **필수 입력 7개**: 소속과 역할 / 해결하려는 문제(한 단락) / 지금까지 시도한 것 / 기대하는 협업 형태(프로젝트 의뢰 · 협업 제안 · 커피챗) / 일정 범위 / 예산 범위 / 연락처. 전부 `required`.
- **처리**: **Formspree**(2026-09-17 승인), AJAX 제출 + 일반 POST 폴백. 상세 [plan-04-contact.md](plan-04-contact.md). `mailto:`는 **기각** — 모바일 웹메일 사용자에게 무반응 링크, 오류 식별(3.3.1) 불가, 본문 템플릿은 지울 수 있어 "무거운 전환"을 스스로 뒤집음. **백엔드 확정 전에는 문의 섹션을 렌더링하지 않는다.**
- **응답 약속**: 명시하지 않는다.

## 최소 공개 단위 (URL을 외부에 공유하는 조건)

① 정의문 ② 확보된 사례 1개(설명·산출물 포함) ③ 팀 10명 이름·역할 ④ 작동하는 연락 수단. 네 가지가 갖춰지기 전에는 `<meta name="robots" content="noindex">`로 배포해 파이프라인만 검증하고 URL을 공유하지 않는다.
이유: 자리표시 `[ ]`가 많은 페이지는 "정직"이 아니라 "미완"으로 읽히고, 첫인상은 한 번 소비되면 돌아오지 않는다(AI Council 3/4 패널).

**필터 전제의 기각 조건**: 2026-12-31까지 유효 문의 N건 미만이면 "설득이 아니라 필터" 전제를 재검토한다. N은 팀이 정한다(미정).

## 디자인 결정 (캔버스 v1에서 확정)

- 컬러 3색만: `#0A0A0A` / `#1E548C` / `#F8F8F6`. 보조 틴트 `#E3ECF5`(썸네일 자리), 캡션 `#5A5A5A`(근백색 위 명암비 **6.5:1**, WCAG 상대휘도식 계산, AA 통과·AAA 미달 — v2의 "7:1"은 오기). 잉크 위 라벨 `#9DBBDB` 10.0:1. **블루 위 잉크 / 잉크 위 블루 조합 금지**(2.5:1).
- 서체: **Pretendard 단일(임시)** — 로고 벡터 확보 전까지 제목 전용 서체를 정하지 않는다(형태 앵커는 로고 획에서 나오므로 근거 없는 결정 회피). 캔버스의 Gothic A1은 시안용. Pretendard dynamic-subset(jsDelivr) 사용.
- 폰트 예산 합계 ≤300KB, LCP ≤2.5s, INP ≤200ms. 390px 실기기에서 측정.
- 포커스 링: 3px 실선 `#1E548C`(근백색 위 7.3:1), offset 3px. 모든 인터랙티브 요소.
- 등장 애니메이션 없음. 움직임 예산은 관계 맵 재도입 시 그쪽에.
- 라운드 20px 이상(카드 28~40px, 필 999px). 획 3px 이상(아웃라인 4px). 기울기 -2 / -1 / +1만.
- 좌측 정렬 기본. 카드 폭·오프셋을 달리해 균등 그리드를 깬다.
- 워드마크 자리는 벡터 원본 확보 전까지 점선 자리표시.

## 이 문서가 결정하지 않은 것

- 모바일 메뉴 형태(현재 캔버스는 햄버거 버튼만)
- 섹션 간 전환 연출(있다면 transform·opacity만, 화면당 1~2개)
- 다크 모드 — 블루 모드 단일 운용이므로 기본은 라이트 근백색
- 다국어 — 국문 단일로 시작
