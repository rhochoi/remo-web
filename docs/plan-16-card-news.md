# 계획 16 — 카드뉴스 제작 원리를 홈에 적용하는 방안

날짜: 2026-10-08. 상태: 방안 탐색 후 **F → A → B → C와 실행 카드 섹션을 구현**(§9). 측정 도구: `docs/tools/card-lint.py`.

## 1. 가져올 원리

출처는 마케팅 블로그와 도구 업체 글이라 연구 근거가 아니라 **실무자 조언**이다([위픽 레터](https://letter.wepick.kr/post/26221), [크몽 아티클](https://kmong.com/article/1012), [PostNitro: 캐러셀 스토리텔링](https://postnitro.ai/blog/post/mastering-carousel-storytelling-engage-your-audience)). 장 수·이탈률 같은 수치("7~10장", "첫 3장에서 절반 이탈")는 글쓴이의 관찰이라 이 저장소의 기준으로 확정하지 않고 눈금으로만 쓴다.

| # | 원리 | 뜻 |
|---|---|---|
| P1 | 디자인 전에 스토리보드 | 장마다 한 줄 문장을 먼저 쓴다. 안 써지면 그 장은 없애거나 나눈다 |
| P2 | 한 장에 한 메시지 | 한 화면이 한 문장만 전달한다 |
| P3 | 첫 장은 훅 | 썸네일 크기에서도 읽혀야 한다 |
| P4 | 짧은 문장, 큰 글씨, 넉넉한 여백 | 모바일은 빽빽함을 바로 벌한다 |
| P5 | 하나의 시스템 | 제목 위치·색 블록 고정. 색 3·글꼴 2·여백 30%는 흔한 권장치 |
| P6 | 리듬 | 사진·글·도식·상호작용을 번갈아 둔다 |
| P7 | 중요한 건 앞에 | 뒤 장은 못 읽힐 수 있다 |
| P8 | 마지막 장은 행동 하나 | 요약하고 다음 걸음 하나만 준다 |

## 2. 현재 홈을 기준표로 쟀다 (`card-lint.py`, 오늘 `site/index.html`)

기준(눈금): 제목 ≤ 24자, 섹션 글자 ≤ 160자(첫 장 ≤ 80), 섹션당 h2 1개, 조작 요소 ≤ 4개.

| 섹션 | 제목 | 글자 | 조작 | 판정 |
|---|---|---|---|---|
| 첫 장(워드마크) | 23 | 77 | 0* | OK |
| 하는 일 | 16 | **226** | 3 | 글자 초과(줄마다 문장+출처 태그) |
| 관계 놀이터 | 17 | 121 | **5** | 조작 초과(유형 3 + 흔들기 + 기울이기) |
| 프로젝트 | 10 | **261** | 4 | 글자 초과(카드마다 설명·단계) |
| 팀 | 21 | 51 | 1 | OK |
| 문의 | 11 | 54 | 1 | OK |

\* 궤도 점 4개는 svg 안이라 집계에서 빠진다. 실제 첫 장 조작은 4개다.
눈금은 비교용이다. 초과 = 고쳐야 한다가 아니라 "한 장에 한 메시지"에서 멀어진 곳을 가리킨다.

## 3. 충돌과 조정: 카드뉴스는 설득이고 리모는 필터다

decisions.md는 "설득이 아니라 필터"라고 했다. 카드뉴스 원리를 그대로 가져오면 절벽형 훅, 이탈 방지, 전환 최적화로 흐른다.

- **가져온다:** P1 P2 P4 P5 P6 P7(명료함과 구조의 공예).
- **조정해서 가져온다:** P3 훅은 **참인 문장**이어야 한다(과장·낚시 금지, 첫 문장은 정의문 그대로). P8 행동은 하나지만 "무겁게" 유지한다(문의 폼의 의도적 마찰).
- **가져오지 않는다:** 이탈 방지용 장치, 공유·저장을 조르는 문구, 가짜 긴급성.

## 4. 적용 방안 (효과·비용·위험 순)

| 안 | 내용 | 효과 | 비용 | 위험 |
|---|---|---|---|---|
| **A. 스토리보드 정리** | 홈을 7장 한 줄 문장으로 먼저 확정(§5). 글자 초과 섹션을 줄이고, 놀이터 조작을 "유형 3개 + 더보기"로 | 큼 | 작음(문구 위주) | 팀 문구 확인 필요(받는/받지 않는 일은 이미 대기 중) |
| **B. 카드 템플릿 규격** | 모든 섹션이 같은 슬롯을 가진다: 상단 좌 라벨, 상단 우 `3/7`, 큰 한 줄, 보조 최대 2줄, 하단 단일 행동. 진행 표시는 장식이 아니라 위치 정보 | 중 | 중(CSS) | 섹션이 틀에 갇혀 놀이터·워드마크의 자유가 줄 수 있음. 슬롯은 필수가 아니라 기본값 |
| **C. 프로젝트 가로 스와이프(모바일)** | 모바일에서 프로젝트 4개를 4:5 카드로 가로 스냅. 카드뉴스의 본래 제스처 | 중 | 작음(`scroll-snap-x`) | 접근성: 키보드 포커스 이동과 스냅이 싸울 수 있음. 데스크톱은 현행 유지 |
| **D. 한 소스, 두 출력** | 장 문구·색·이미지를 `cards.json` 한 곳에 두고 홈 섹션과 **SNS용 1080×1350 PNG**를 같은 템플릿에서 뽑는다 | 큼(Moodism 펀딩 홍보 등 실제 수요) | 큼(렌더 스크립트, 헤드리스 브라우저 필요) | 새 도구 의존. 브랜드 가이드 v4의 SNS 모드(소프트 3D·주황)와 맞춰야 함 |
| **E. 섹션별 공유 카드** | `#card-3` 같은 앵커와 장별 og 이미지 | 작음 | 중 | 필터 철학과 거리가 있음(공유 유도). 보류 권장 |
| **F. 표지 시험** | 첫 화면을 1/4 크기로 줄여도 "무엇을 하는 누구인가"가 읽히는지 점검 | 중 | 작음 | 없음 |

**권장 순서:** F(점검) → A(문구 확정) → B(규격) → C(모바일 스와이프). D는 SNS 홍보 일정이 정해졌을 때 별도 계획으로. E는 하지 않는다.

## 5. 7장 스토리보드 (초안, 문구는 모두 기존 사이트·노션 확정 문장)

| 장 | 역할 | 한 줄 | 근거 |
|---|---|---|---|
| 1 | 표지·훅 | 문제를 받아 실행으로 증명하는 열 명의 학생 협동조합. | 현행 h1 |
| 2 | 방법 | 데이터 분석, 디자인, 프로토타입으로 끝까지. | 현행 sub, 줄(row) 3개는 2장 안 펼침으로 |
| 3 | 증거 | 지금 하고 있는 네 가지 일. | 현행 projects. 중요한 건 앞에(P7)라 맵보다 앞으로 |
| 4 | 방식 | 열 명이 맞물린 방식을 이름 없이. | 현행 놀이터 |
| 5 | 필터 | 받는 일과 받지 않는 일. | **문구 합의 대기**(structure.md 섹션 2) |
| 6 | 사람 | 포지션 없이, 열 명이 문제 하나를 끝까지. | 현행 team |
| 7 | 행동 | 문제를 적어 보내 주세요. | 현행 contact |

현재 순서(하는 일 → 놀이터 → 프로젝트 → 팀 → 문의)에서 바뀌는 것은 **프로젝트를 놀이터 앞으로** 올리는 것 하나뿐이다.

## 6. 카드 규격 (B·D의 공통 기준, 제안)

- 웹 카드: 기본 높이 1화면(`svh`), 슬롯 5개(라벨 / `n/7` / 큰 한 줄 / 보조 ≤ 2줄 / 행동 ≤ 1). 큰 한 줄 ≤ 24자(2줄), 보조 ≤ 60자.
- SNS 카드(D): 1080×1350(4:5). 안전 여백 96px, 제목 상단 고정, 색은 브랜드 모드 하나(주황 또는 블루), 글꼴 Pretendard.
- 색 3·글꼴 1은 이미 지키고 있다. 여백 30%는 측정 방법을 아직 정하지 않았다.

## 7. 결정 요청

1. A~F 중 진행할 것(권장: F → A → B → C).
2. 프로젝트를 놀이터 앞으로 올려도 되는지(§5).
3. D(SNS 카드 출력)를 지금 계획할지, 홍보 일정이 잡힌 뒤로 미룰지.
4. "받는 일 / 받지 않는 일" 문구 합의 일정(5장이 이 문구를 기다린다).

## 8. 한계

- 원리의 출처가 실무 블로그뿐이고 장 수·이탈 수치는 검증되지 않았다.
- 기준표는 글자 수·요소 수만 잰다. 위계, 리듬, 읽기 편함은 재지 못했다.
- 방문자 행동 데이터(스크롤 깊이, 문의율)가 없어 어떤 안이 실제로 낫다고 단정할 수 없다. 결정 기록의 "유입 없으면 사이트를 고치지 말 것" 원칙도 여전히 유효하다.
- 이 문서는 제안이다. 사이트 코드는 바꾸지 않았다.

## 9. 구현 기록 (2026-10-08)

**F. 표지 시험(1/4 크기, 256px 폭):** h1과 워드마크는 읽힌다. 문제 두 가지를 고쳤다: 워드마크가 폭의 약 70%라 작아 보임(좁은 화면에서 114% 폭으로 확대), 내비 글자 "REMO CORE"가 줄바꿈됨(360px 미만에서 글자 숨김).
**A. 스토리보드:** 홈을 7장으로 정리했다. 표지 → 하는 일 → 프로젝트 → **실행의 장면(신설)** → 관계 → 팀 → 문의. 프로젝트를 관계 앞으로 올렸다(중요한 건 앞에). "받는 일 / 받지 않는 일"은 문구 합의 전이라 넣지 않았다. 글자 줄이기: "하는 일"의 두 번째 문장(첫 장 부제와 중복)과 출처 태그를 덜어냈다. 팀이 확정한 문장 자체는 바꾸지 않았다.
**B. 카드 슬롯:** 장의 위치는 오른쪽 pager(≥1100px, 7점)가 알려 준다. 장면 카드는 라벨 / 큰 한 줄 / `n / 7` / 마지막 장 행동 하나의 슬롯을 따른다. 나머지 섹션을 같은 틀에 가두지는 않았다.
**C. 모바일 스와이프:** ≤899px에서 프로젝트를 가로 스냅 카드로 바꿨다. 다음 카드가 비쳐 넘길 수 있음을 알린다.
**신설: 실행의 장면(카드뉴스).** 4:5 카드 7장. 표지, 프로젝트 실행 경험 TS 2장, Moodism 샘플 2장, PLN 화면, 단체 사진(마지막 장에 문의 행동 하나). 사진 4장은 저장소에 있었으나 연결되지 않았던 자산(`card-*.jpg`로 경량화, 합계 약 390KB).

**기준표 변경(정직하게 기록):** lint를 v2로 바꿨다. 목록형 섹션(하는 일·프로젝트·장면)은 섹션 전체 글자 수가 아니라 **카드 한 장당 90자, 카드 밖 120자**로 잰다. 카드뉴스의 원리가 장 단위이기 때문이지만, 측정 결과를 보고 기준을 조정한 것이라는 점은 밝혀 둔다. v1 기준으로는 프로젝트(261자)가 여전히 초과다. 놀이터 조작은 숨김 버튼(기울이기, 터치 기기에서만 노출)을 제외해 4개다.

**팀 확인 필요(사진 문구):**
- `workshop.jpg`에 "프로젝트 실행 경험 TS · 2026.06.08"을 붙였다. 같은 방·같은 인물로 보이는 기존 히어로 사진의 캡션을 따른 추정이다.
- Moodism 두 장의 설명("샘플을 큰 종이 위에 펼쳐 놓고", "어깨의 단추 디테일")은 사진에 보이는 것만 적었다. 몇 차 샘플인지는 쓰지 않았다.
- 단체 사진 벽면 간판의 장소명은 쓰지 않았다.
- 프로젝트 카드의 "펀딩 2026.09.23 → 10.07 예정"은 오늘(10.08) 기준 이미 지난 일정일 수 있다. 사실 확인 전까지 바꾸지 않았다.
