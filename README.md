# REMO

리모는 열 명의 학생 협동조합입니다. 이 저장소는 함께 있는 장면과 각자가 남긴 작업, 그 사이에서 생기는 관계를 담는 웹사이트입니다.

## 우리가 중심에 두는 것

**사람과 관계가 먼저입니다.** 무엇을 만들었는지는 사람을 만나는 하나의 입구입니다. 결과물이나 역할이 한 사람을 전부 설명하지는 않습니다.

서로 다른 사람들이 어떤 말을 건네고, 무엇을 함께 해보고, 어떻게 영향을 주고받는지에 관심을 둡니다. 이 문장은 모든 팀원이 같은 성격이나 방식으로 움직인다는 선언이 아닙니다. 각자의 차이를 지우지 않는 것이 중요합니다.

**처음부터 모두 이해할 필요는 없습니다.** 방문자가 한 장면에 머물거나, 마음에 드는 기록만 보거나, 나중에 다시 와도 괜찮습니다. 사이트가 먼저 리모를 요약하고 해석해 줄 필요는 없습니다.

이 웹사이트의 우선 목적은 방문자를 선별하거나 문의를 계약으로 전환하는 것이 아닙니다. 사람과 장면을 만나고, 궁금해진 만큼 더 들여다볼 수 있는 공간을 만듭니다.

## 화면을 만드는 태도

- **설명을 서두르지 않습니다.** 사진, 말, 작업 흔적이 먼저 놓일 수 있습니다. 제목이나 문구는 이해를 돕는다는 이유만으로 자동으로 추가하지 않습니다. 그렇다고 모든 글을 없애지는 않습니다. 당사자의 말과 목소리도 중요한 재료입니다.
- **서로 다른 표현을 허용합니다.** 사진 한 장, 짧은 문장, 스케치, 작업물은 다른 크기와 방식으로 등장할 수 있습니다. 사람을 같은 프로필 카드나 성격 태그에 맞추지 않습니다.
- **장난기를 꾸며내지 않습니다.** 실제로 주고받은 말, 예상 밖의 시도, 미완성의 흔적에서 출발합니다. 흔들리는 도형이나 둥근 버튼만으로 팀의 성격을 대신하지 않습니다.
- **형식을 철학으로 착각하지 않습니다.** 격자, 곡률, 정렬, 기울기는 표현 수단입니다. 언제나 써야 하거나 절대로 쓰면 안 되는 브랜드 성격으로 고정하지 않습니다.
- **낯설어도 조작은 어렵지 않게 합니다.** 내용을 즉시 해석할 필요는 없지만, 이동·열기·닫기는 예측할 수 있어야 합니다. 중요한 정보를 hover에만 숨기지 않습니다.

바꿀 때는 이렇게 묻습니다.

> 이 선택은 사람과 흔적이 드러날 자리를 만드는가, 아니면 우리가 보여야 할 모습을 대신 설명하고 있는가?

이 질문이 모든 이미지에 설명이나 관계 서사를 붙이라는 요구는 아닙니다. 그냥 남겨두어도 좋은 장면이 있습니다.

## 로고·색·글·움직임

실제 REMO 워드마크를 사용하고 원본의 비율과 윤곽을 보존합니다. 로고를 반복하거나 크게 놓는 것만으로 정체성을 만들려 하지 않습니다.

오션 블루 `#1E548C`를 현재 웹의 브랜드 색으로 유지합니다. 사진과 작업물 자체의 색을 제한하지 않습니다. 색의 면적과 배치는 콘텐츠에 맞춰 판단합니다.

서체와 여백은 읽기와 분위기를 함께 고려합니다. 큰 제목, 작은 주석, 동일한 크기의 카드가 기본 답은 아닙니다. 첫 화면에 모든 내용을 넣을 의무도 없습니다.

움직임은 보고 만지는 경험에 의미가 있을 때 씁니다. 새로운 효과나 라이브러리를 추가하기 전에 기존 HTML·CSS와 브라우저 기능으로 충분한지 확인합니다. 모션 감소 설정, 키보드 포커스, 읽기 대비, 모바일 사용성은 지킵니다.

## 기록을 다루는 약속

실제 자료와 당사자가 남긴 말에 근거합니다. 없는 대화, 성격, 관계, 성과, 실패를 만들어 빈자리를 채우지 않습니다. 팀의 기록을 특정 개인의 단독 발언으로 바꾸지 않습니다.

미완성과 의견 차이를 보여줄 수 있다는 말은 사적인 대화나 갈등을 공개하라는 뜻이 아닙니다. 사람의 의도와 공개 범위를 존중합니다. 자료를 읽을 수 있다는 사실과 외부 게시에 대한 허락은 구분합니다.

날짜와 출처는 필요한 곳에서 찾아볼 수 있게 둡니다. 관찰한 사실과 우리의 해석을 구분하며, 확인되지 않은 것을 확정된 설명으로 쓰지 않습니다.

## 현재 작업과 문서의 우선순위

2026-09-18 기준 로컬 검토본은 사람들의 장면으로 시작하고, 작업·메모·기록이 이어집니다. 소개와 자세한 배경은 선택해서 열어봅니다. 이 화면은 현재의 시도이며 최종적인 리모의 모습으로 고정하지 않습니다.

이 README는 현재 대화에서 정한 디자인 방향입니다. 과거 `docs/` 문서의 방문자 필터·계약률 목표, 곡률·기울기 절대 규칙, 한 화면에 모든 내용 배치 등의 지침은 현재 방향으로 사용하지 않습니다. 충돌할 경우 최신 사용자 결정과 이 문서를 우선합니다. 과거 문서는 결정의 이력으로 보존합니다.

화면이 정상 작동하는지와 리모답게 느껴지는지는 따로 검토합니다. 자동 검사 통과가 디자인의 적합성을 증명하지는 않습니다.

## 저장소와 로컬 실행

- `site/`: 정적 웹사이트. 현재 `index.html`과 `concept.html`은 같은 검토본입니다.
- `docs/`: 자료 출처, 판단 기록, 이전 시안과 검토 이미지.
- `tests/concept.cjs`: 화면 너비, 이미지 확대, 키보드, 펼침 등 브라우저 검사.
- `.github/workflows/pages.yml`: `main` 푸시 또는 수동 실행 시 `site/`를 GitHub Pages에 배포하도록 구성된 워크플로. 실제 배포 성공 여부는 별도 확인합니다.

```sh
python3 -m http.server 8766 --bind 127.0.0.1 --directory site
```

Playwright와 Chrome이 준비된 환경에서:

```sh
node tests/concept.cjs
```

검사는 기본적으로 `http://127.0.0.1:8766`에 접속합니다. 다른 주소는 `BASE_URL`로 지정합니다. 현재 axe 자동 검사는 `/tmp/axe.min.js`가 있을 때만 실행되므로, 없으면 접근성 검사까지 통과했다고 표현하지 않습니다.

로컬 수정과 외부 게시를 구분합니다. Git push·업로드·배포는 사용자 지침에 따른 직전 승인 후 진행합니다.
